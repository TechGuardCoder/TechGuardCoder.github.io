NK Node

2026 · Tech Guard · nknode.com

Problem

Small organizations need to see what they run, find what is exposed, and fix it, without a security team. Their scan results are a map of their weaknesses, so that data should stay on their own machine. An agent that can change systems is a new attack surface of its own.

What I built

  • A self hosted appliance for Linux, macOS and Windows. It inventories devices, servers, websites, cloud accounts and code repositories, with the software and versions each one runs.
  • Network scans, web app scans against the OWASP Top 10, and code scanning for vulnerable dependencies, code issues and leaked keys, matched against CVE feeds, CISA KEV and EPSS.
  • A SIEM over syslog, endpoint and router logs, with detection rules and an alert queue.
  • Hermes as the orchestration layer. Agents triage alerts, hunt, and propose fixes. Hermes reasons; NK Node decides.

Security decisions

  • Scan data never leaves the appliance. Vulnerability matching runs against local copies of OSV, the CVE List, KEV and EPSS. What the appliance downloads is the same whatever the inventory holds, and the tests fail on any network call.
  • Agents ask first by default. Every feature where an agent changes something is set to off, ask first, or automatic. Automatic needs an admin and the organization's name typed. One switch pauses all of it, and everything done without a person is logged and announced.
  • Each agent gets the least it needs. MCP tool profiles scope each client. The built in assistant only reads. The engineering bots get vulnerability advice and nothing about the site's hosts, logs or alerts.
  • Leaked keys are cleared without being kept. A leaked key becomes a pull request that removes it, a revocation or rotation step, and an optional history purge. Each step asks first. The value is never stored, logged, or sent to the model.
  • An outside test, then fixes. A test report on October 26 found six issues, including SSRF in website checks, trusted forwarding headers that could be forged, a known default admin password, and no CSP. All six were fixed and merged two days later.
  • The tradeoff: local matching means downloading about 1.1 GB of OSV exports and keeping them in sync, instead of asking an API. I chose the disk and bandwidth over sending a list of a client's vulnerable software to a third party.

Result

NK Node runs on Tech Guard's network. A public release is in preparation: the release candidate installs with one command that checks release checksums, from a pipeline with a hashed dependency lock.

Next: hardening under review, including role checks on containment approval, fencing outside text in agent prompts, and a hash chained audit log.
